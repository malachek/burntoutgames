# burntoutgames.com

The Burnt Out Games studio site. Plain HTML and CSS, generated by one Node
script with **zero dependencies** — nothing to `npm install`, no lockfile,
nothing that can break because a package updated.

```
content/          Everything the site says. Plain JSON. The CMS edits these.
public/           Files copied to the site as-is: logos, patterns, CSS, JS, /admin
lib/              The templates and the Markdown renderer
brand/            The brand system and voice guide the site is built from
build.mjs         Reads content/ + public/, writes dist/
serve.mjs         Local preview server
dist/             The built site. Generated — never edit, never commit.
```

## 1. Preview it on your Mac

You need Node 18 or newer. Check by opening **Terminal** and running:

```bash
node -v
```

If that prints a version number like `v22.x.x`, you're set. If it says "command
not found", install it from [nodejs.org](https://nodejs.org) (take the LTS
button) and reopen Terminal.

Then, from this folder:

```bash
cd ~/Documents/bog-website
node build.mjs
node serve.mjs
```

Open **http://localhost:4321**. Press `Ctrl+C` in Terminal to stop it.

Every time you change something in `content/`, run `node build.mjs` again and
refresh. (`npm run dev` does both in one command.)

## 2. Put it on GitHub

Cloudflare needs to read the site from a Git repository, and the admin panel
writes changes back to it. This is a one-time setup.

1. Go to [github.com/new](https://github.com/new).
2. Name it `burntoutgames`. Set it to **Private** if you'd rather. Do **not**
   tick "Add a README" — this folder already has one.
3. Click **Create repository**. GitHub shows you a page of commands. Ignore it
   and use these instead, in Terminal:

```bash
cd ~/Documents/bog-website
git init
git add .
git commit -m "Burnt Out Games website"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/burntoutgames.git
git push -u origin main
```

Replace `YOUR-USERNAME` with your GitHub username. If it asks for a password,
it wants a *personal access token*, not your account password — GitHub will
walk you through it, or install [GitHub Desktop](https://desktop.github.com)
and do the whole step by clicking instead.

> **A note on the `references/` folder.** It contains the brand guide and your
> raw marketing notes. `git add .` will push those to GitHub too. If the repo is
> public and you'd rather they weren't, add a line saying `references/` to
> `.gitignore` **before** you run `git add .`.

## 3. Deploy to Cloudflare Pages

1. In the [Cloudflare dashboard](https://dash.cloudflare.com), open
   **Workers & Pages** → **Create** → **Pages** → **Connect to Git**.
2. Authorise GitHub and pick the `burntoutgames` repository.
3. On the build settings screen, set exactly this:

   | Field | Value |
   |---|---|
   | Framework preset | **None** |
   | Build command | `node build.mjs` |
   | Build output directory | `dist` |
   | Root directory | *(leave empty)* |

4. Click **Save and Deploy**.

It takes about a minute. You'll get a URL like
`burntoutgames.pages.dev` — open it and check the site works.

**From now on, every push to `main` rebuilds and redeploys automatically.** You
will never run these steps again.

## 4. Point burntoutgames.com at it

Your domain is already on Cloudflare, which makes this short.

1. First, **remove the redirect to Figma.** In the Cloudflare dashboard select
   the `burntoutgames.com` domain, then look in **Rules → Redirect Rules** (and
   **Rules → Page Rules** if anything is there) and delete or disable the rule
   pointing at `burntoutgames.figma.site`. If the redirect was set up as a DNS
   record instead, you'll find it in **DNS** as a `CNAME` on `@` or `www` — note
   it, you're about to replace it.
2. Go back to **Workers & Pages** → your `burntoutgames` project → **Custom
   domains** → **Set up a custom domain**.
3. Enter `burntoutgames.com`, confirm. Cloudflare adds the DNS record itself.
4. Repeat for `www.burntoutgames.com` so both work.

SSL is automatic. Give it a few minutes, then load https://burntoutgames.com.

## 5. Turn on the admin panel

This is what gets you form fields instead of code. It's the fiddliest part of
the setup and it's still only about fifteen minutes, once, forever.

The admin panel lives at `burntoutgames.com/admin`. It needs permission to write
to your GitHub repo, and GitHub only grants that through a small piece of
software called an OAuth app. Cloudflare runs that for free.

**5a. Deploy the authenticator.**

Go to [github.com/sveltia/sveltia-cms-auth](https://github.com/sveltia/sveltia-cms-auth)
and click the **Deploy to Cloudflare Workers** button in its README. It walks
you through deploying to your own Cloudflare account. When it finishes you'll
have a URL like:

```
https://sveltia-cms-auth.YOUR-SUBDOMAIN.workers.dev
```

Copy it.

**5b. Register the OAuth app on GitHub.**

Go to [github.com/settings/applications/new](https://github.com/settings/applications/new) and fill in:

| Field | Value |
|---|---|
| Application name | `Burnt Out Games CMS` |
| Homepage URL | `https://burntoutgames.com` |
| Authorization callback URL | `https://sveltia-cms-auth.YOUR-SUBDOMAIN.workers.dev/callback` |

Register it. On the next page copy the **Client ID**, then click **Generate a
new client secret** and copy that too. The secret is shown once.

**5c. Give the worker the keys.**

Back in Cloudflare: **Workers & Pages** → `sveltia-cms-auth` → **Settings** →
**Variables and Secrets**. Add:

| Name | Value | Type |
|---|---|---|
| `GITHUB_CLIENT_ID` | your Client ID | Text |
| `GITHUB_CLIENT_SECRET` | your Client Secret | **Secret (encrypted)** |
| `ALLOWED_DOMAINS` | `burntoutgames.com` | Text |

Save and deploy the worker.

**5d. Point the CMS at both.**

Open `public/admin/config.yml` and change the two lines marked `CHANGE ME`:

```yaml
backend:
  name: github
  repo: YOUR-USERNAME/burntoutgames
  branch: main
  base_url: https://sveltia-cms-auth.YOUR-SUBDOMAIN.workers.dev
```

Save, then push:

```bash
git add . && git commit -m "Configure CMS" && git push
```

**5e. Log in.** Go to `https://burntoutgames.com/admin`, click **Sign in with
GitHub**, approve. You should see Games, Devlog, Team and Site settings in the
sidebar.

## 5b. Turn on the contact form

The form at `/contact/` posts to `/api/contact`, which is a Cloudflare Pages
Function in `functions/api/contact.js`. Cloudflare compiles it automatically;
it just needs three settings and a verified sender.

1. Make a free account at [resend.com](https://resend.com) and add
   `burntoutgames.com` as a domain. Resend gives you two or three DNS records.
2. Add those records in Cloudflare under your domain's **DNS** tab, exactly as
   Resend shows them. Wait for Resend to say Verified (usually minutes).
3. In Resend, create an **API key** and copy it.
4. In Cloudflare: **Workers & Pages** → your `burntoutgames` project →
   **Settings** → **Variables and Secrets**, add:

   | Name | Value | Type |
   |---|---|---|
   | `RESEND_API_KEY` | the key you copied | **Secret (encrypted)** |
   | `CONTACT_TO` | `info@burntoutgames.com` | Text |
   | `CONTACT_FROM` | `BOG Site <site@burntoutgames.com>` | Text |

5. Redeploy (any push does it) and send yourself a test message.

Until those variables exist the form answers "The form is not configured yet."
rather than failing silently. The email address is also on the page, so nobody
is ever stuck.

The form has a hidden honeypot field and length limits on every input, which
handles the great majority of spam without a CAPTCHA.

## 6. Editing the site afterwards

### Through the admin panel (the normal way)

Go to `burntoutgames.com/admin`, change a field, click **Publish**. That writes
to GitHub, Cloudflare notices, rebuilds, and the change is live in about a
minute. You can do this from your phone.

- **Change a tagline or any homepage text** → Site settings → Global text
- **Add a devlog post** → Devlog → New Post
- **Add a game** → Games → New Game (set the URL slug carefully, it's permanent)
- **Add key art or screenshots** → open the game, use the image fields
- **Add a team member** → Team → New Team member

### By editing files (if you prefer)

Everything the CMS edits is a plain JSON file in `content/`. Change it, run
`node build.mjs` to check it locally, then commit and push.

### Reviewing all the copy at once

Run `node copy-review.mjs`. It writes `COPY-REVIEW.md` — every editable string
on the site in one file, each with the exact field it maps to. Read it, mark up
what you want changed, and either edit the field yourself or send the file back.
It regenerates from `content/`, so it can never be out of date.

> **Note:** brand assets are deliberately not offered for public download.
> Press enquiries get files by email.

## 7. What still needs your input

The site is complete and deployable as-is. These are the gaps I couldn't fill
without you.

**Individual LinkedIn links.** All ten team members are on the studio page with
their real photos and roles, but the Figma site renders its profile links with
JavaScript, so I couldn't read the URLs off it. Add each one under Team → the
person → "LinkedIn or portfolio" and a Profile link appears under their role.
The company LinkedIn is already in the footer.

**Ansh's headshot is low-resolution.** The source file is a small, soft crop, so
it's noticeably softer than the other nine at the size the grid uses. A newer
photo would fix it. Everything else was white-balanced and exposure-matched to
sit together.

**Game screenshots.** Each game now uses its real key art and logo, and Burning
Out has one in-game screenshot. More screens, especially for EXO, would fill the
"Screens" section on each game page. Add them under Games → the game →
Screenshots.

**The headline font.** The brand guide specifies Nexa Rust Slab, a commercial
Fontfabric typeface that needs a paid webfont licence to embed. The site ships
**Alfa Slab One**, a free Google Fonts slab doing the same job. If you buy the
licence, `brand/BRAND-SYSTEM.md` §2 has the one-line swap.

**Discord invite.** Every "Join the community" button currently points at your
Linktree. Add the real invite under Site settings → Discord invite URL and they
all switch over.

**Two claims to confirm.** The press kit says "Based: California, United States"
and the boilerplate says "founded in 2024 by a team of game design students".
Both come from your own notes rather than a public source.

**Kawai'ian Isolation's numbers.** Your notes record 10,000 claims in the first
100 hours. It's a strong number and it is deliberately still off the site,
because a press kit is the one place an unverifiable figure does real damage. If
you can produce the Steam screenshot, add it as a fact on the game and on the
press page.

## 8. Troubleshooting

**The build stops and lists problems.** That's deliberate — it validates content
before writing anything, so a missing field can't quietly publish a broken page.
Each line names the file and the field. Fix and re-run.

**A page 404s after deploying.** Check the Cloudflare build log
(Workers & Pages → your project → the latest deployment). Nine times in ten the
build command or output directory is wrong: they must be `node build.mjs` and
`dist`.

**The admin panel says "Failed to authenticate."** The callback URL in your
GitHub OAuth app must match the worker URL exactly, with `/callback` on the end
and no trailing slash. Check `ALLOWED_DOMAINS` on the worker includes
`burntoutgames.com`.

**The admin panel loads but shows no collections.** `config.yml` didn't parse.
YAML is whitespace-sensitive — check indentation on whatever you last changed.

**Fonts look wrong locally but fine online.** The site loads fonts from Google
Fonts, so it needs an internet connection. Offline it falls back to a system
serif.

**I changed a colour and nothing happened.** Studio colours live in
`public/styles/tokens.css`. Each game's own colours live in that game's
`theme` block, editable under Games → the game → Game colours.

**A game's card looks wrong after I changed its art.** Two things control it.
"Key art focal point" decides which part of a wide image survives cropping
(`center 70%` favours the lower half). "Game colours" has to be re-picked from
the new art, and every text colour there needs 4.5:1 against its background.

## Reference

- `brand/BRAND-SYSTEM.md` — colour, type, logo, pattern and accessibility rules,
  with the measured contrast values behind each decision
- `brand/VOICE-AND-MESSAGING.md` — taglines, the three registers, banned words,

disagree, the files are wrong — update them.
